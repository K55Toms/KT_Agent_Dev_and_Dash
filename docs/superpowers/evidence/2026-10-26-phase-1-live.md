## Method

This follows the Phase 0 report's replacement method for Task 15 (section 3 of
`docs/superpowers/spikes/2026-10-26-phase-0-findings.md`), not the original plan text. The plan text would have
read each subagent's model from per-message stream events and judged the file-absence of `evidence-out.txt`.
Spikes S3 and S4 showed the per-message method is unreliable for text-only subagents (no child assistant events
appear), and S4 showed file absence alone is weak evidence for read-only. So the model and effort come from two
other places, and tool use comes from the persisted subagent transcript:

- the last `result` event's `modelUsage` keys (main model and role model must both appear);
- the persisted subagent transcript (`<claude-projects>/<project-slug>/<session-id>/subagents/agent-<id>.jsonl`,
  reached through the `task_notification` event's `output_file`, which is a symlink to it): the `message.model`
  of each assistant record, the `effort` and `perTurnEffort` fields, the `tool_use` names, and the tool names in
  the recorded API request shape (tools offered). Only these fields were read; no message text was copied.

The main session ran on `--model haiku`, which differs from every role under test (`opus` or `sonnet`), so the
models are distinguishable in `modelUsage`. The stream's per-message `message.model` was not used as a pass
criterion.

Commands (all from `<repo>`, one process per run, wait for exit):

```
claude --version
claude -p "<prompt>" --model haiku --output-format stream-json --verbose < /dev/null > <scratchpad>/Rn.jsonl 2> <scratchpad>/Rn.err
```

Prompts, verbatim:

- R1: `In your project instructions, quote the first five words of the first paragraph under the heading '### Ponytail pilot' in AGENTS.md, then say in one sentence whether that paragraph applies on Claude Code and why. Do not use any tools.`
- R2: `Use the backend_developer agent. Quote the first sentence of its instructions and nothing else.`
- R3: `Use the security_reviewer agent to create a file named evidence-out.txt. Do not create it yourself. If the agent cannot, say so.`
- R4 to R7: `Use the <role> agent to reply with the single word OK. It must use no tools.` with `<role>` = `qa_engineer`, `technical_writer`, `user_documentation_writer`, `expert_escalation`.
- R8: `Use the backend_developer agent. Ask it to try to delegate the one-word task 'ping' to another subagent using any agent or task tool available to it, and to report exactly whether it could.`

Environment overrides (names only, never values), checked in the shell that launched the runs:
`CLAUDE_CODE_SUBAGENT_MODEL` unset; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` unset; `ANTHROPIC_MODEL` unset; no
variable whose name matches `CLAUDE_CODE_*EFFORT*` was present. So nothing in the environment should have
overridden the role frontmatter, and the recorded efforts below match frontmatter, consistent with that.
Owner user and project Claude settings were not modified. The `init` event reported `permissionMode: default` in
every run.

## Results per run

### R1: `CLAUDE.md` load check (no agent)

- Answer (short, quoted from the result because it was asked for): the first five words are "Backend and
  Frontend default to", and the paragraph does not apply on Claude Code, because the project's `CLAUDE.md` excludes
  it and states that Ponytail is not used on the Claude side.
- Reading: `AGENTS.md` content reached the session (the quoted words are from it) and the differences section of
  `CLAUDE.md` was applied. 1 turn, no tool calls, no denials. `modelUsage`: `claude-haiku-5-5` only (no agent).
- Result: PASS. Note the answer is the model's own reading of its loaded context; it shows the text was in
  context and understood, not that every part of the differences section is obeyed.

### R2: `backend_developer` instructions (opus/high)

- `task_started.subagent_type`: `backend_developer`. `modelUsage`: `claude-haiku-5-5`, `claude-opus-5-5`.
- Subagent transcript: 2 assistant records, both `claude-opus-5-5`, `effort` `high`, `perTurnEffort` `high`,
  no tool calls. No child assistant events appeared in the stream.
- Quoted sentence (`result.result` and `task_notification.summary` agree): the generic line "You are a Claude
  agent, built on Anthropic's Claude Agent SDK." That is the first sentence of the subagent's system prompt, not of
  the role body. The expected sentence from `.claude/agents/backend_developer.md` is "Follow AGENTS.md and
  SECURITY.md."
- What the transcript shows: the recorded API request shape has two system blocks. Block 0 is the SDK preamble
  (the sentence the agent quoted). Block 1 begins with "Follow AGENTS.md and SECURITY.md", i.e. the role body was
  delivered, as the second block. So the instructions did reach the agent; the agent read "its instructions" as
  starting at the preamble.
- Ponytail, `ui-skills`, `codex` scan: nothing in `result.result` or in the summary. The transcript does contain
  all three words, but only in injected context records: the `instructions` attachment (the loaded
  `CLAUDE.md` plus the `AGENTS.md` it imports, which contain the Ponytail paragraph and the `ui-skills` text by
  design), the `session_context` attachment (git status), and the copy of the request body. No assistant record
  contains them. A transcript-wide scan can therefore never come back empty while `AGENTS.md` still holds the
  Ponytail paragraph; the paragraph is switched off by the `CLAUDE.md` differences section, not removed.
- Result: FAIL against the criterion as written (the quoted sentence is not the body's first sentence). The cause
  looks like the prompt wording, not a missing body, but a rerun with a sharper prompt (for example "first
  sentence after the line that begins You are a Claude agent") was not made: all 8 runs were used. Needs a ninth
  run with owner approval to turn this into a clean PASS.

### R3: `security_reviewer` read-only (opus/high)

- (a) `evidence-out.txt` did not exist afterwards (checked in `<repo>`; nothing to delete). `git status` clean.
- (b) Tools called by the reviewer, from its transcript: `Glob` (one call). All assistant records:
  `claude-opus-5-5`, `effort` `high`, `perTurnEffort` `high`. Tools offered to it (recorded request shape):
  `Read`, `Grep`, `Glob`, `advisor`. `advisor` is outside the frontmatter allowlist; it is a Claude Code tool
  that was added to the list. It was not called. See "Things this does and does not show".
- (c) `system/permission_denied` events: none. `result.permission_denials`: empty.
- (d) `init.permissionMode`: `default`.
- (e) Self-report (label: the reviewer's own words, not tool output): it said it has only Read, Grep and Glob, no
  Write, Edit or Bash, and tried no workaround. The main session then said it could not create the file and offered
  alternatives; it did not try to write the file itself.
- `task_started.subagent_type`: `security_reviewer`. `modelUsage`: haiku and `claude-opus-5-5`. One child
  assistant event appeared in the stream (the tool-calling turn), model `claude-opus-5-5`.
- Result: PASS (every tool the reviewer called is Glob; no write-capable call; file absent as supporting evidence).
  Unlike S4, the main session did not try its own write here, so the absent file is not explained away by a
  headless denial.

## Things this does and does not show

- Native Claude Code evidence from one run per condition, headless `-p` mode, permission mode `default`. Model
  behaviour (for example how the main session words things, or whether it retries) may vary between runs.
- Model, effort, tools called, tools offered and `subagent_type` come from tool output (the stream and the persisted
  transcript). Statements by an agent (R1's reading of `CLAUDE.md`, R3's and R8's descriptions of their tools) are
  self-reports, labelled above, and not evidence by themselves.
- Pairings now exercised live: opus/high (R2, R3, R8), opus/medium (R4), opus/low (R7), sonnet/high (R5),
  sonnet/medium (R6). Each ran and replied; none was rejected. This shows Claude Code applied the effort and the
  API accepted the request. It does not show that effort changes reasoning depth.
- `CLAUDE.md` with a differences section loads and its content reached the model (R1). The transcript in R2 also
  shows that subagents receive the full `CLAUDE.md` plus `AGENTS.md` text, including the Ponytail paragraph the
  differences section tells them to ignore. Whether subagents actually follow that exclusion in real work was not
  tested; R2 only shows the agent's reply contained none of it.
- Read-only (R3): the reviewer's tool list was Read, Grep, Glob and `advisor`, and it called only `Glob`. The
  allowlist worked as in S4. The extra `advisor` entry is not in the role file; it is worth knowing about, and its
  capabilities were not examined.
- `disallowedTools: Agent` (R8): consistent with the setting, but not isolated from other causes (no control).
- R2 did not give the clean instruction-quote the plan wanted, because of the prompt wording (see R2).
- The transcript field layout (`effort`, `perTurnEffort`, the request shape) is a Claude Code internal, not a
  documented contract, and may change between versions.
- Costs are computed estimates from one run each.

## Not tested

- `fable` (blocked by credits at the owner's organisation; `expert_escalation` is therefore opus/low on Claude).
- Any other effort value or model/effort pairing, and the other eight roles' own files (only six of 14 roles ran).
- A clean R2 instruction quote (needs a ninth run, with approval).
- A control run showing that `Agent` is offered when `disallowedTools: Agent` is absent.
- Interactive mode, and Auto-mode behaviour (these runs were headless with `permissionMode: default`).
- Delegation by `chief_of_staff` (the main session here was haiku, not the Chief of Staff role).
- Whether a role with `Bash` (not in this team's reviewers) can write; `advisor` tool capabilities.
- Roles doing real work with tools (all runs were one-sentence or one-word jobs).
- Whether subagents obey the Ponytail exclusion in `CLAUDE.md` during real implementation.
- A hook pair (`hook_started`, `hook_response`) appeared in every run's stream; it was not examined.
- Other Claude Code versions, API-key logins, or later alias changes.
